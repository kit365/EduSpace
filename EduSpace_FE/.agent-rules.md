## 🚫 QUY TẮC 1 — KHÔNG TỰ Ý COMMIT

- **TUYỆT ĐỐI KHÔNG** chạy `git commit` dưới bất kỳ hình thức nào mà chưa có
  xác nhận rõ ràng từ người dùng.
- Bao gồm tất cả các biến thể:
  ```
  git commit
  git commit -m "..."
  git commit -am "..."
  git commit --amend
  ```
- Nếu cần commit, Agent PHẢI:
  1. Thông báo danh sách file thay đổi (`git status`)
  2. **Đề xuất** commit message
  3. **CHỜ** người dùng xác nhận "OK" hoặc "Commit đi"
  4. Chỉ sau khi nhận xác nhận mới được thực thi

## 🚫 QUY TẮC 2 — KHÔNG TỰ Ý PUBLISH / PUSH / DEPLOY

## 🚫 QUY TẮC 3 — DANH SÁCH LỆNH BỊ CẤM (BLOCKED COMMANDS)

> Các lệnh dưới đây bị **CẤM HOÀN TOÀN**. Agent **KHÔNG ĐƯỢC** tự ý thực thi
> dưới bất kỳ hoàn cảnh nào. Nếu cần thiết, PHẢI giải thích lý do và
> **CHỜ xác nhận rõ ràng** từ người dùng.

### NHÓM 1 — CỰC KỲ NGUY HIỂM (Hủy dữ liệu, khó/không khôi phục)

| Lệnh | Mô tả | Mức độ |
|---|---|---|
| `rm -rf` | Xóa đệ quy + không hỏi, có thể xóa toàn bộ hệ thống | 🔴 CRITICAL |
| `rm -r` | Xóa thư mục và toàn bộ nội dung bên trong | 🔴 CRITICAL |
| `rm` | Xóa file trực tiếp, không qua thùng rác | 🔴 CRITICAL |
| `unlink` | Xóa file ở mức filesystem, không thể undo | 🔴 CRITICAL |
| `shred` | Ghi đè dữ liệu nhiều lần để không thể phục hồi | 🔴 CRITICAL |
| `wipe` | Xóa dữ liệu vĩnh viễn trên disk | 🔴 CRITICAL |
| `dd` | Ghi/chép block thô, dễ phá hủy disk hoặc partition | 🔴 CRITICAL |
| `dd if=/dev/zero` | Ghi số 0 lên thiết bị, xóa sạch dữ liệu | 🔴 CRITICAL |
| `dd if=/dev/null` | Làm hỏng nội dung thiết bị nếu dùng sai | 🔴 CRITICAL |
| `mkfs` / `mkfs.ext4` / `mkfs.xfs` | Tạo filesystem mới, xóa sạch dữ liệu cũ | 🔴 CRITICAL |
| `format` | Format ổ đĩa (Unix / Windows) | 🔴 CRITICAL |
| `Format-Volume` | PowerShell format volume | 🔴 CRITICAL |

### NHÓM 2 — NGUY HIỂM CAO (Xóa thư mục / nhiều file)

| Lệnh | Mô tả | Mức độ |
|---|---|---|
| `rmdir` | Xóa thư mục (thường là thư mục rỗng) | 🟠 HIGH |
| `rd` | Xóa thư mục trong Windows | 🟠 HIGH |
| `rmdir /s` | Xóa thư mục và toàn bộ nội dung (Windows) | 🟠 HIGH |
| `Remove-Item -Recurse` | PowerShell xóa đệ quy thư mục và file | 🟠 HIGH |
| `Remove-Item` | PowerShell xóa file / thư mục | 🟠 HIGH |
| `del /s` | CMD xóa nhiều file trong thư mục con | 🟠 HIGH |
| `erase /s` | CMD xóa hàng loạt file | 🟠 HIGH |

### NHÓM 3 — NGUY HIỂM TRUNG BÌNH (Xóa file / ghi đè)

| Lệnh | Mô tả | Mức độ |
|---|---|---|
| `del` | Xóa file trong Windows | 🟡 MEDIUM |
| `erase` | Tương đương del | 🟡 MEDIUM |
| `Clear-Content` | Xóa nội dung file nhưng giữ file | 🟡 MEDIUM |
| `cp --remove-destination` | Ghi đè file đích bằng cách xóa trước | 🟡 MEDIUM |

### NHÓM 4 — NGUY HIỂM GIÁN TIẾP (Di chuyển / đồng bộ xóa)

| Lệnh | Mô tả | Mức độ |
|---|---|---|
| `mv` | Di chuyển / ghi đè file, mất dữ liệu cũ | 🟡 MEDIUM |
| `rsync --delete` | Xóa file ở đích nếu không còn ở nguồn | 🟡 MEDIUM |
| `rsync --remove-source-files` | Di chuyển file bằng cách xóa nguồn | 🟡 MEDIUM |
| `install` | Ghi đè file hệ thống khi cài đặt | 🟡 MEDIUM |

### NHÓM 5 — Quản lý Disk / Partition (Rủi ro cao nếu dùng sai)

| Lệnh | Mô tả | Mức độ |
|---|---|---|
| `fdisk` | Chỉnh sửa partition table | 🟠 HIGH |
| `cfdisk` | fdisk dạng giao diện | 🟠 HIGH |
| `parted` | Quản lý partition nâng cao | 🟠 HIGH |
| `diskpart` | Công cụ partition của Windows | 🟠 HIGH |
| `mount` | Gắn filesystem (ghi đè mount point) | 🟡 MEDIUM |
| `umount` | Tháo filesystem, có thể mất dữ liệu đang ghi | 🟡 MEDIUM |

### NHÓM 6 — Ít nguy hiểm nhưng có thể gây hậu quả

| Lệnh | Mô tả | Mức độ |
|---|---|---|
| `truncate` | Cắt ngắn file (có thể về 0 byte) | 🟡 MEDIUM |
| `chown` | Đổi owner, có thể làm mất quyền truy cập | ⚪ LOW |
| `chmod` | Đổi permission, có thể khóa file | ⚪ LOW |
| `attrib` | Thay đổi thuộc tính file (Windows) | ⚪ LOW |

## 📂 QUY TẮC 8 — CẤU TRÚC DỰ ÁN

Agent cần tuân thủ cấu trúc thư mục hiện tại của dự án:

```
EduSpace_FE/
├── src/
│   ├── admin/              # Admin Panel
│   │   ├── features/admin/ # Admin features (pages, components, hooks, data, types)
│   │   ├── layouts/        # Admin layouts
│   │   └── routes/         # Admin routing
│   ├── client/             # Customer-facing (User Mode)
│   │   └── features/       # Customer features
│   ├── host/               # Host Console
│   │   └── features/       # Host features
│   ├── components/         # Shared components
│   ├── types/              # Shared TypeScript types
│   ├── i18n/               # Internationalization (vi, en)
│   └── ...
├── public/
├── .agent-rules.md         # ← FILE NÀY
└── package.json
```

- **KHÔNG** tạo file/thư mục ngoài cấu trúc trên mà không hỏi.
- **KHÔNG** di chuyển file giữa các module (admin ↔ client ↔ host) mà không hỏi.
- File mới phải đặt đúng theo quy tắc phân loại:
  - Trang mới → `features/<module>/pages/`
  - Component mới → `features/<module>/components/`
  - Type mới → `src/types/`
  - Mock data → `features/<module>/data/`
  - Hooks → `features/<module>/hooks/`

## 🌐 QUY TẮC 9 — I18N (ĐA NGÔN NGỮ)

- Khi tạo hoặc chỉnh sửa UI text, **PHẢI** cập nhật cả 2 file:
  - `src/i18n/locales/vi.ts` (Tiếng Việt)
  - `src/i18n/locales/en.ts` (English)
- **KHÔNG** hardcode text trực tiếp trong JSX nếu đã có hỗ trợ i18n cho
  module đó.
- Key i18n phải tuân theo cấu trúc phân cấp rõ ràng:
  `module.section.fieldName` (ví dụ: `host.register.pageTitle`)

## � QUY TẮC 10 — API & DATA FETCHING

- **LUÔN** sử dụng `apiClient` từ `src/lib/axios.ts`.
- **KHÔNG** sử dụng `native fetch` hoặc khởi tạo instance axios mới trong components.
- **TRÁNH** hardcode URL trực tiếp. Sử dụng các hằng số định nghĩa trong `src/config/api/`.
- **I18N support**: `apiClient` đã được cấu hình tự động đính kèm header `Accept-Language`. Tuyệt đối không xóa logic này.

## 🔔 QUY TẮC 11 — TOAST & FEEDBACK

- **TUYỆT ĐỐI** không sử dụng `window.alert()` hoặc `window.prompt()`.
- **LUÔN** sử dụng `sonner` toast cho các thông tin phản hồi (success, error, loading).
- Khuyến khích sử dụng wrapper utility (nếu có) để đảm bảo tính nhất quán.

---

## 🏗️ QUY TẮC 12 — CẤU TRÚC FEATURE-BASED

- Mỗi feature lớn trong `src/client/features/` hoặc `src/admin/features/` PHẢI chứa đầy đủ:
  - `components/`: UI riêng của feature.
  - `services/`: Các hàm gọi API (sử dụng `apiClient`).
  - `hooks/`: Custom hooks xử lý logic hoặc logic fetch dữ liệu (React Query).
  - `types/`: Định nghĩa kiểu dữ liệu riêng.
