## 🏗️ PHẦN 1 — KIẾN TRÚC HỆ THỐNG (MICROSERVICE)

### 1.1 Tổng quan kiến trúc

Hệ thống EduSpace Backend sử dụng kiến trúc **Microservice** với các thành phần:

| Service | Mô tả | Port |
|---|---|---|
| `discovery-server` | Eureka Server — Danh bạ dịch vụ | 8761 |
| `api-gateway-service` | Spring Cloud Gateway — Cổng vào duy nhất | 8080 |
| `account-service` | Quản lý tài khoản, xác thực (Keycloak) | 8081 |
| `booking-service` | Quản lý đặt phòng/lịch học | 8082 |

### 1.2 Cấu trúc Root

```
EduSpace_BE/
├── .agent-rules.md              # ← FILE NÀY — Luật cho Agent
├── .cursorrules                 # Cursor-specific rules
├── .env                         # Biến môi trường (KHÔNG commit secrets)
├── docker-compose.yml           # Docker orchestration
├── realm-export.json            # Keycloak realm config
│
├── discovery-server/            # Eureka Server (Infrastructure)
├── api-gateway-service/         # API Gateway (Infrastructure)
├── account-service/             # Business Service
└── booking-service/             # Business Service
```

### 1.3 Quy tắc Module

- **KHÔNG** tạo module mới mà không hỏi người dùng.
- **KHÔNG** tạo file Java ngoài package `com.eduspace.<service-name>`.
- **KHÔNG** tạo thư mục con ngoài cấu trúc phân layer đã định.
- Mỗi service PHẢI có: `pom.xml`, `Dockerfile`, `application.yml`.
- Mỗi service PHẢI đăng ký với Eureka (trừ `discovery-server`).

### 2.3 Quy tắc phân layer (NGHIÊM NGẶT)

| Layer | Package | Chức năng | Được phép gọi |
|---|---|---|---|
| Presentation | `presentation/` | REST Controllers, API Paths | → Business |
| Business | `business/` | Service Interface + Impl | → Model, Persistence, Infrastructure |
| Model | `model/` | Entity, DTO, Mapper | Không gọi ai |
| Persistence | `persistence/` | Repository (Data Access) | → Model |
| Infrastructure | `infrastructure/` | Config, Init, External Services | → Business, Model |
| Common | `common/` | Enums, Utils dùng chung | Không gọi ai |
| Exception | `exception/` | Error/Success Codes, Handler | Được gọi bởi tất cả |

**QUY TẮC BẮT BUỘC:**
- Controller **KHÔNG** chứa business logic. Chỉ nhận request → gọi Service → trả response.
- Service layer **KHÔNG** xử lý i18n (bản dịch). Dùng `MessageSource` tại Controller.
- Service **KHÔNG** trả về `ResponseEntity`. Chỉ trả DTO hoặc throw `AppException`.
- Infrastructure **KHÔNG** chứa business logic (validation, tính toán).
- Entity **KHÔNG** nằm trong package `dto` và ngược lại.

| Loại file | Đặt tại |
|---|---|
| REST Controller mới | `presentation/controller/` |
| API Path constants | `presentation/constants/` |
| Service Interface | `business/service/` |
| Service Implementation | `business/serviceimpl/` |
| JPA Entity | `model/entity/` |

**KHÔNG** tự ý tạo package mới ngoài danh sách trên mà chưa hỏi người dùng.

### 2.5 Quy tắc Unit Testing (BẮT BUỘC)

- **MỌI** logic nghiệp vụ mới PHẢI đi kèm với Unit Test.
- **Framework**: Sử dụng JUnit 5 + Mockito + AssertJ (có sẵn trong `spring-boot-starter-test`).
- **Phạm vi coverage**:
    - **Service Layer**: Mock Repositories và các Service khác. Kiểm tra luồng logic, throw exception.
    - **Controller Layer**: Mock Services. Kiểm tra HTTP logic, validation, i18n keys.
- **Naming**: `[ClassName]Test.java` (vd: `UserServiceImplTest.java`).
- **Cấu trúc test**: Tuân thủ mẫu `src/test/java/com/eduspace/<servicename>/...` tương ứng với package của source code.

## 📐 PHẦN 3 — QUY TẮC CODE

### 3.1 API Response Standard

Tất cả API PHẢI trả về `ApiResponse<T>` duy nhất:

```json
{
  "success": true,
  "timestamp": "2026-03-04T10:15:30Z",
  "status": 200,
  "code": "USER_REGISTER_SUCCESS",
  "message": "Đăng ký tài khoản thành công",
  "data": {}
}
```

- `success` phản ánh đúng trạng thái (true/false).
- `status` khớp HTTP status code.
- `code` lấy từ enum (`SuccessCode` hoặc `ErrorCode`).
- `message` KHÔNG hardcode — phải lấy từ `MessageSource` (i18n).
- Mọi error đều qua `GlobalExceptionHandler`.
- Controller KHÔNG trả `ResponseEntity` thô.

### 3.2 Constants & Enums

- **KHÔNG** hardcode chuỗi cho: API paths, Role names, Error messages, URLs.
- API paths → `ApiPaths.java` trong `presentation/constants/`.
- Role names → `Role.java` enum trong `common/enums/`.
- Error/Success codes → Enum trong `exception/`.

### 3.3 I18n (Đa ngôn ngữ)

- Mỗi key i18n mới → cập nhật **CẢ 2** file: `messages.properties` + `messages_vi.properties`.
- Service layer **KHÔNG** xử lý bản dịch. Controller inject `MessageSource`.
- Key tuân theo format: `<domain>.<action>.<result>` (vd: `user.register.success`).

### 3.4 Database

- Flyway cho migration. File đặt tại `resources/db/migration/`.
- Đặt tên: `V<number>__<description>.sql` (vd: `V2__add_booking_table.sql`).
- **KHÔNG** tự ý xóa hoặc sửa file migration đã có.

### 3.5 Cấu hình

- Tất cả giá trị nhạy cảm (secrets, passwords, URIs) → lấy từ `.yml` hoặc `.env`.
- **KHÔNG** hardcode secret trong annotation hoặc class Java.
- Dùng `${}` placeholder: `${KEYCLOAK_ISSUER_URI:http://localhost:8180/realms/eduspace}`.

## 🚫 PHẦN 4 — AN TOÀN HỆ THỐNG

### 4.1 KHÔNG TỰ Ý COMMIT / PUSH / DEPLOY

- **TUYỆT ĐỐI KHÔNG** chạy bất kỳ lệnh nào sau mà chưa có xác nhận:
  ```
  git commit / git push / git push --force
  npm publish / firebase deploy / vercel --prod
  ```
- Nếu cần commit → Phải thông báo danh sách file, đề xuất message, **CHỜ** xác nhận.

### 4.2 DANH SÁCH LỆNH BỊ CẤM

| Nhóm | Lệnh | Mức độ |
|---|---|---|
| Xóa dữ liệu | `rm -rf`, `rm -r`, `rm`, `shred`, `wipe` | 🔴 CRITICAL |
| Ghi đè hệ thống | `dd`, `mkfs`, `format` | 🔴 CRITICAL |
| Git nguy hiểm | `git reset --hard`, `git clean -fd`, `git push -f`, `git branch -D` | 🔴 CRITICAL |
| Xóa thư mục | `rmdir`, `rd /s`, `Remove-Item -Recurse` | 🟠 HIGH |
| Di chuyển/ghi đè | `mv`, `rsync --delete` | 🟡 MEDIUM |

Tất cả lệnh trên **PHẢI** có xác nhận trước khi thực thi.

### 4.3 KHÔNG TỰ Ý THAY ĐỔI CẤU TRÚC THƯ MỤC

- **KHÔNG** tạo, đổi tên, di chuyển, xóa **thư mục** mà chưa có xác nhận.
- **KHÔNG** đổi tên file mà chưa có xác nhận.
- Khi cần thay đổi → Liệt kê rõ → Giải thích lý do → **CHỜ** xác nhận.

### 4.4 HÀNH VI ĐƯỢC PHÉP (KHÔNG CẦN XÁC NHẬN)

| Hành vi | Ví dụ |
|---|---|
| Đọc file | `cat`, `view_file`, `grep`, `find` |
| Tạo file **mới** (theo đúng kiến trúc) | `write_to_file` với `Overwrite: false` |
| Chỉnh sửa nội dung file đã có | `replace_file_content`, `multi_replace_file_content` |
| Chạy build / test | `mvn compile`, `mvn test`, `mvn clean package` |
| Xem git status | `git status`, `git log`, `git diff` |
| Xem trạng thái hệ thống | `ls`, `pwd`, `java -v`, `mvn -v` |
